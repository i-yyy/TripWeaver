# Travel Agent 当前 Skill 说明

本文档基于当前项目第二版 skill 实现整理，说明每个 skill 的命中条件和功能说明，便于前端联调、测试和验收。

## 1. 总体说明

- 当前 skill 分为两类：
  - `static`：基于用户输入直接命中
  - `dynamic`：基于天气、日期等运行时结果补充命中
- 当前系统会对 skill 数量做上限控制：
  - `hard / dynamic-hard` 优先保留
  - `style` 类 skill 可能因为数量上限被挤掉
- 当前结果页展示的 `applied_skills`，就是最终真正生效的 skill，不是所有候选 skill。

## 2. Static Skills

### 2.1 `budget_guard`

- 中文名称：预算守卫
- 类型：`static` + `hard`
- 命中条件：
  - 预算等级为 `low`
  - 或补充要求/画像/记忆/RAG 文本中出现“省钱”“便宜”“高性价比”“budget”等关键词
- 功能说明：
  - 优先选择免费或低门票景点
  - 优先选择经济型、高性价比酒店
  - 在规划阶段控制景点、餐饮、交通的整体花费
  - 在后置校验阶段检查预算是否明显超出低预算档位

### 2.2 `dietary_safe`

- 中文名称：饮食安全
- 类型：`static` + `hard`
- 命中条件：
  - 饮食限制包含 `vegetarian`
  - 或饮食限制包含 `halal`
  - 或饮食限制包含 `no_spicy`
- 功能说明：
  - 三餐安排必须符合饮食限制
  - 餐饮描述会强调为什么符合限制
  - 在后置校验阶段检查三餐是否违背饮食约束
  - 会压制 `food_explorer`

### 2.3 `low_mobility`

- 中文名称：低步行负担
- 类型：`static` + `hard`
- 命中条件：
  - 行动需求包含 `less_walking`
  - 或行动需求包含 `wheelchair`
  - 或行动需求包含 `rest_friendly`
  - 或补充要求中出现“少走路”“无障碍”“行动不便”“老人”“low walking”“wheelchair”等关键词
- 功能说明：
  - 降低单日景点数量和步行强度
  - 优先安排更近、更易达的景点和交通方式
  - 路线说明中强调休息点和低强度衔接
  - 在后置校验阶段限制一天内过多景点或过重步行负担

### 2.4 `family_friendly`

- 中文名称：亲子友好
- 类型：`static` + `style`
- 命中条件：
  - 同行人群包含 `family`
  - 或补充要求中出现“亲子”“家庭”“带娃”“小朋友”等关键词
- 功能说明：
  - 降低日程密度，避免过晚或过赶
  - 加强用餐和休息衔接
  - 倾向选择家庭更容易接受的景点类型

### 2.5 `food_explorer`

- 中文名称：美食优先
- 类型：`static` + `style`
- 命中条件：
  - 兴趣偏好或旅行风格中出现 `food`
  - 或补充要求中出现“美食”“小吃”“探店”“food”“好吃”等关键词
- 功能说明：
  - 强化餐饮在行程中的存在感
  - 尽量让三餐与当天路线联动
  - 突出本地特色餐饮和时段合理性
- 说明：
  - 若同时命中 `dietary_safe`，通常会被压制

### 2.6 `transit_first`

- 中文名称：公共交通优先
- 类型：`static` + `style`
- 命中条件：
  - 交通方式为 `Public Transit`
- 功能说明：
  - 优先选择公共交通更易到达的景点
  - 优先选择靠近地铁或公共交通节点的酒店
  - 减少跨区移动，强化换乘清晰度

### 2.7 `drive_friendly`

- 中文名称：自驾友好
- 类型：`static` + `style`
- 命中条件：
  - 交通方式为 `Drive`
- 功能说明：
  - 更接受稍远但串联性更好的景点组合
  - 酒店选择更偏向停车方便
  - 路线说明中强调停车和顺路逻辑

### 2.8 `checkin_spots`

- 中文名称：经典打卡
- 类型：`static` + `style`
- 命中条件：
  - 旅行风格包含 `checkin`
  - 或补充要求中出现“打卡”“拍照”“出片”等关键词
- 功能说明：
  - 提高地标景点、热门景点、拍照点的权重
  - 行程会更强调经典路线和拍照友好时段
- 说明：
  - 可能被 `weekend_peak_avoidance` 压制

### 2.9 `local_immersion`

- 中文名称：本地体验
- 类型：`static` + `style`
- 命中条件：
  - 旅行风格包含 `local`
  - 或补充要求中出现“本地人”“不想太游客化”“local”等关键词
- 功能说明：
  - 更偏向本地感、街区感、在地体验
  - 餐饮更倾向本地特色建议
  - 适合配合 RAG 或本地知识片段增强解释性

### 2.10 `couple_romantic`

- 中文名称：情侣氛围
- 类型：`static` + `style`
- 命中条件：
  - 同行人群包含 `couple`
- 功能说明：
  - 行程更偏向轻松、约会氛围
  - 更容易安排傍晚、夜景、氛围型餐饮内容

## 3. Dynamic Skills

### 3.1 `rainy_day`

- 中文名称：雨天备选
- 类型：`dynamic` + `dynamic-hard`
- 命中条件：
  - 补充要求/画像/记忆/RAG 文本中出现“下雨”“雨天”“雨”“rain”“indoor”“室内”等关键词
  - 或天气结果中出现“雨”“rain”“storm”等天气信号
- 功能说明：
  - 优先安排室内或半室内景点
  - 减少长距离户外步行
  - 在结果中明确给出雨天备选说明
  - 后置校验会补充雨天执行建议

### 3.2 `heat_avoidance`

- 中文名称：高温避暑
- 类型：`dynamic` + `dynamic-hard`
- 命中条件：
  - 天气结果中白天气温达到高温阈值，目前实现为 `day_temp >= 30`
  - 或补充要求中出现“怕热”“避暑”“中午别太晒”等关键词
- 功能说明：
  - 重点活动更偏向上午和傍晚
  - 中午增加休息或室内安排
  - 降低正午高强度户外移动
  - 后置校验会补充避暑提醒和节奏修补

### 3.3 `weekend_peak_avoidance`

- 中文名称：周末避峰
- 类型：`dynamic` + `dynamic-hard`
- 命中条件：
  - 出行日期覆盖周六或周日
  - 且补充要求/画像/记忆/RAG 文本中出现“不想太挤”“避开人多”“错峰”等关键词
- 功能说明：
  - 尽量错峰安排热门景点
  - 加入预约、提前出发、避峰时段提醒
  - 降低多个热门点堆叠在同一高峰时段的概率
  - 会压制 `checkin_spots`

## 4. 当前主要抑制关系

### 4.1 `dietary_safe` 压制 `food_explorer`

- 原因：
  - 饮食安全属于硬约束，优先级高于纯美食偏好

### 4.2 `weekend_peak_avoidance` 压制 `checkin_spots`

- 原因：
  - 周末避峰属于动态硬约束，优先级高于热门打卡偏好

## 5. 前端验证建议

- 验单个 skill 时，尽量一次只填一个主目标
- 不要在一次请求里同时勾选过多风格偏好，否则可能因为数量上限被挤掉
- 结果页里展示的“已启用技能”即最终生效结果，优先以该区域为准
